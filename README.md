# AI-редактор

Рабочее пространство для русскоязычного текста: черновик, проверка ошибок, AI-правка,
сравнение версий и экспорт собраны в одном интерфейсе. Можно начать с пустого поля,
вставить текст или загрузить документ, затем просмотреть замечания и решить, какие
изменения принять.

**Открыть редактор:** [GitHub Pages](https://goviks.github.io/ai-editor-assistant/)
**Сервер API:** [Vercel](https://ai-editor-assistant.vercel.app/)

Опубликованный сервер пока работает без подключённого ключа языковой модели и использует
локальный режим коррекции. Для полноценной синтаксической и стилистической редактуры
подключите API-ключ провайдера в окружении backend. Ключ хранится только на сервере.

## Возможности

- **Улучшить** — AI предлагает литературную правку текста или выделенного фрагмента.
- **Сократить** — AI предлагает более компактную редакцию; результат стоит проверить,
  чтобы убедиться, что нужные подробности и смысл сохранены.
- **Стриминг ответа** — текст появляется по словам, а не через 10 секунд ожидания.
- **Сравнение до/после** — после AI-правки исходник и результат доступны рядом,
  с количеством слов и их разницей.
- **Отмена** — запрос обрывается на полуслове, полученное сохраняется.
- **Понятные ошибки** — неверный ключ, лимит запросов, таймаут, пустой ответ: у каждой
  ошибки своё сообщение и подсказка.
- **Проверка орфографии и грамматики** — замечания подсвечиваются в тексте,
  есть переход по ним, фильтры по типам (орфография, пунктуация, грамматика, стиль),
  счётчик ошибок на 100 слов и кнопка «Применить безопасные».
- **Исправление в один клик** — для отдельных замечаний можно применить замену;
  безопасные замены собираются для пакетного применения.
- **Свой словарь** — слова, которые не нужно считать ошибками (термины, названия),
  добавляются в один клик и запоминаются в браузере.
- **Загрузка файлов** — перетащите `.txt`, `.md`, `.docx` или PDF в редактор
  или выберите файл кнопкой «Файл». Текст из PDF извлекается локально в браузере
  без OCR.
- **Повторы слов** — редактор предлагает замену для повторяющихся слов, когда находит
  подходящий вариант.
- **История версий** — каждое исправление и вставка сохраняются в истории,
  историю можно восстановить после перезапуска браузера и сравнить с текущей версией.
- **Ссылки на правила** — для замечаний LanguageTool доступна карточка правила
  в публичной библиотеке сервиса.
- **Строгость проверки** — режимы «мягко», «строго» и «только ошибки».
- **Личная статистика** — число проверок, найденных замечаний, принятых правок
  и время последней проверки; данные сохраняются локально в браузере.
- **Светлая и тёмная темы** — выбор сохраняется локально.
- **Метрики текста** — символы, слова, приблизительные показатели воды, повторов,
  читаемости и времени чтения; обновляются при каждом изменении текста.
- **Черновик сохраняется** — текст не теряется при обновлении страницы.
- **Экспорт** — готовый текст скачивается как `.txt` или `.docx`, а PDF
  формируется через системное окно печати браузера.
- **Горячие клавиши** — `Ctrl + Enter` запуск, `Esc` отмена.
- **Мобильная версия** — панель ассистента выезжает снизу.

Метрики воды, повторов, читаемости и условная оценка в стиле Главреда рассчитываются
локальными упрощёнными эвристиками. Это ориентиры для редактуры, а не официальные оценки
Главреда или доказательство качества текста.

## Как устроена редактура

1. **Начните с черновика.** Вставьте текст, загрузите файл или откройте пример.
2. **Найдите места для внимания.** Проверьте орфографию и грамматику, отфильтруйте
   замечания и перейдите к подсвеченному фрагменту.
3. **Сохраните контроль над текстом.** Примите подходящие исправления по одному,
   примените безопасные замены или запросите AI-вариант. Сравните результат с исходником.
4. **Завершите работу.** Вернитесь к предыдущей версии или экспортируйте отредактированный
   текст.

Такой поток опирается на знакомые пользователям редакторов паттерны: заметная подсветка
ошибок и пояснения к ним, отдельные диагностические сигналы для стиля и повторов,
персональный словарь и возможность принять либо отклонить правку. Сервисы, на которые
ориентировались при обзоре публичных интерфейсов, перечислены в разделе
[«Принципы интерфейса и источники»](#принципы-интерфейса-и-источники).

## Технологии

Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS · Zustand · OpenAI API

## Запуск на Windows

Нужен Node.js 20 или новее.

```powershell
cd ai-editor-assistant
npm install
Copy-Item .env.local.example .env.local
npm run dev
```

Откройте http://localhost:3000

### Настройки

Файл `.env.local`:

```
OPENAI_API_KEY=sk-...   # ключ OpenAI
OPENAI_MODEL=gpt-4o-mini
AI_MOCK=1               # демо-режим без ключа
LANGUAGETOOL_URL=http://localhost:8010/v2/check  # необязательно: свой LanguageTool
```

`AI_MOCK=1` включает локальный режим без языковой модели и исходящих AI-запросов.
Он исправляет только очевидные орфографические и часть пунктуационных ошибок; глубокий
разбор грамматики, морфологии и синтаксиса он не заменяет. Без ключа и `AI_MOCK=1`
сервер вернёт ошибку конфигурации вместо имитации полноценной AI-редактуры.

Для провайдера, совместимого с Chat Completions API, задайте на backend:

```
OPENAI_API_KEY=секретный-ключ-провайдера
OPENAI_MODEL=имя-доступной-модели
OPENAI_BASE_URL=https://api.openai.com/v1
AI_MAX_OUTPUT_TOKENS=2400
```

Для другого провайдера поменяйте `OPENAI_BASE_URL` и `OPENAI_MODEL` на выданные им
значения. Например, для DeepSeek используется `https://api.deepseek.com/v1` и доступное
аккаунту имя модели. Не добавляйте ключ во frontend, Git или Pages variables. Для
локальной модели можно указать URL на `localhost`; для удалённых сервисов разрешён только
HTTPS. Увеличенный лимит ответа помогает редактировать длинные фрагменты без обрыва.

Модель получает отдельные инструкции для режимов «Улучшить» и «Сократить»: анализировать
структуру предложений, грамматические связи и пунктуацию, сохранять факты, отрицания,
условия и авторскую интонацию, не дополнять исходник выдумками. Это снижает риск
повреждения смысла, но не гарантирует безошибочную редактуру — результат нужно вычитать.
В локальном fallback намеренно не удаляются целые предложения и не обрезается конец текста.

## Ограничения проверки

- Проверка текста — до 50 000 знаков за один запрос; сервер проверяет документ
  частями по 5000 знаков.
- Поддерживаются текстовые PDF размером до 5 МБ; сканы без текстового слоя
  требуют OCR и не распознаются.
- Не больше 20 проверок за 10 минут с одного адреса (настраивается переменной
  `CHECK_RATE_LIMIT`).
- Одинаковые тексты кешируются на 5 минут — повторная проверка не тратит лимит.
- По умолчанию текст отправляется в публичный LanguageTool. Чтобы обрабатывать
  его на своём экземпляре, задайте `LANGUAGETOOL_URL` с адресом его `/v2/check`.
- Если LanguageTool недоступен, включаются встроенные правила. При нескольких
  экземплярах приложения лимиты и кеш пока хранятся в памяти каждого процесса.

Черновик, история, словарь, тема и статистика хранятся в `localStorage` текущего
браузера: это не облачная синхронизация и не резервное копирование аккаунта. При запуске
проверки или AI-редактуры текст отправляется с браузера на API; по умолчанию LanguageTool
обрабатывает текст через публичный API. Для конфиденциальных текстов подключите собственный
экземпляр LanguageTool и настройте политику обработки данных перед использованием.
PDF импортируется локально в браузере и экспортируется через системную печать. OCR,
аккаунты и облачная синхронизация пока не поддерживаются.

## Принципы интерфейса и источники

Публичные сайты проверены 29 октября 2026 года. Изучались общие продуктовые паттерны,
а не копировались тексты, визуальный стиль или закрытые функции сервисов:

- [Главред](https://glvrd.ru/) — быстрый анализ информационного стиля и сигнализация
  словесного мусора. Для редактора полезен принцип: метрика должна помогать заметить
  проблему, но окончательное решение остаётся за автором.
- [Тургенев](https://turgenev.ashmanov.com/) — диагностика повторов, читаемости и
  стилистических рисков с наглядной оценкой.
- [Орфограммка](https://orfogrammka.ru/) — цикл «вставить текст → получить замечания
  и пояснения → принять решение» и персональный словарь.
- [LanguageTool](https://languagetool.org/) — подсветка замечаний прямо в тексте,
  категории ошибок, персональный словарь и управление строгостью проверки.
- [Текст.ру](https://text.ru/) — пример объединения нескольких текстовых задач в одной
  экосистеме. В этот проект не включаются плагиат-чекер, AI-детектор, Telegram-бот или
  другие инструменты, не относящиеся к редактуре.

Поэтому главный сценарий здесь — не безусловный автоматический рерайт, а понятная
последовательность: **написать → проверить → оценить предложение → принять правку →
сравнить и экспортировать**. Подсветка и фильтры помогают быстро ориентироваться, а
сравнение и история сохраняют контроль автора над результатом.

## Деплой на Vercel

1. Загрузите проект в GitHub.
2. Откройте [vercel.com/new](https://vercel.com/new) и выберите репозиторий.
3. В настройках проекта добавьте `OPENAI_API_KEY` (или `AI_MOCK=1` для демо).
4. Нажмите Deploy.

Каждый `git push` после этого собирается автоматически.

## Публикация через GitHub Pages

GitHub Pages размещает статический интерфейс. Рабочие AI- и проверки API остаются
на существующем Vercel-деплое `https://ai-editor-assistant.vercel.app`; Pages
обращается к нему по HTTPS. Сервер разрешает API-запросы с origin
`https://goviks.github.io`. Текст, отправленный на AI-обработку или проверку,
передаётся этому Vercel API так же, как при использовании основного сайта.

Workflow `.github/workflows/pages.yml` собирает отдельный Vite frontend и
публикует его в GitHub Pages при push в `main`. После первого успешного запуска
сайт доступен по адресу
https://goviks.github.io/ai-editor-assistant/.

## Локальная сборка Pages

```powershell
$env:GITHUB_PAGES = "true"
$env:NEXT_PUBLIC_API_BASE_URL = "https://ai-editor-assistant.vercel.app"
$env:NEXT_PUBLIC_PDF_WORKER_URL = "/ai-editor-assistant/pdf.worker.min.mjs"
npm run pages:build
```

Статические файлы появятся в `out/`. Для работы API нужен доступный Vercel backend;
сборка Pages сама по себе серверные API-маршруты не размещает.

## Структура проекта

```
app/            страницы и API-маршрут ассистента
components/     интерфейс: редактор, панель ответа, метрики и общий футер
lib/ai/         правила текста, работа с моделью, демо-режим
lib/server/     интеграции API, LanguageTool, CORS и лимиты
lib/store/      состояние редактора и ответа
pages-site/     отдельная статическая сборка для GitHub Pages
types/          общие типы
docs/           аудит, заметки и скриншоты
```
