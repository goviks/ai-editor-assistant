## 2. Статистика, которую можно использовать

- **Орфограммка:** 150 000+ авторов и 50 000+ проверок в месяц — это средний
  размер аудитории нишевого сервиса проверки текста на русском.
- **LanguageTool:** 2000+ организаций и 3–4 млн установок расширений — верхняя
  граница рынка, достигнутая за счёт интеграций, а не за счёт «умной проверки».
- **Главред и Advego:** бесплатные инструменты с платными API/подписками —
  монетизация строится на B2B-интеграции и на объёме, а не на розничной подписке.
- **Текст.ру:** с 2011 года и 10+ смежных инструментов — выживают не «проверкой
  орфографии», а экосистемой вокруг текста.

**Вывод:** рынок зрелый, «проверка орфографии» сама по себе не дифференцирует.
Выигрывает тот, кто закрывает весь путь текста: написать → проверить → улучшить →
сократить → выгрузить.

## 3. Где мы отстаём (gap-анализ)

### Проверка текста
1. Морфология и падежи («согласно договора») — нет собственного разбора.
2. Лексические и семантические ошибки (смешение паронимов, «власть предержащие»).
3. Ёфикация и настройка «буква ё».
4. Проверка ударений.
5. Подбор синонимов и замена повторов.
6. Фильтр по типам ошибок (орфография / пунктуация / стиль).
7. Ссылка на правило у каждой ошибки.
8. Проверка уникальности текста.
9. Определение «написано нейросетью».
10. Персональный словарь терминов.

### Редактор
11. Подсветка ошибок прямо в тексте (у нас список).
12. Переход «следующая/предыдущая ошибка».
13. Применение всех безопасных правок одной кнопкой.
14. История версий и откат.
15. Автосохранение в аккаунте, а не только в браузере.
16. Загрузка файла (docx/pdf/txt) и проверка документа.
17. Экспорт в DOCX/PDF с сохранением правок.
18. Комментарии и режим «предложений» для редактора.
19. Счётчик изменений и «до/после» в одном экране.
20. Настройка строгости проверки (мягко / строго / только ошибки).

### Интерфейс
21. Тёмная и светлая темы.
22. Онбординг с примером текста и подсказками.
23. Прогресс проверки и понятные пустые состояния.
24. Панель «что изменилось» после улучшения.
25. Мобильный редактор с крупными кнопками.
26. Горячие клавиши для проверки и применения правок.
27. Drag & drop файла в редактор.
28. Индикатор «сколько ошибок на 100 слов».

### Интеграции
29. Браузерное расширение для проверки на любом сайте.
30. Telegram-бот.
31. API для команд и CMS.
32. Плагины Word / Google Docs.
33. Десктоп-приложение или офлайн-режим.

### Данные и развитие
34. Личная статистика: сколько ошибок, какие чаще, прогресс.
35. Аналитика для команд и отчёты по документам.
36. Синонимайзер и перефраз на уровне предложения.
37. Суммаризация длинных документов.
38. Сравнение двух версий текста.
39. SEO-блок: ключевые слова, тошнота, вода.
40. Проверка «под аудиторию»: тон, стиль, читательский уровень.

## 4. Приоритетный план

### P0 — без этого продукт не воспринимается как редактор (2–3 недели)
| Изменение | Зачем | Эффект |
| --- | --- | --- |
| Подсветка ошибок в тексте и навигация по ним | главный паттерн рынка | +30–50% к числу применённых правок |
| Кнопка «Применить все безопасные» | экономит время | выше возврат в продукт |
| Фильтр по типам ошибок | убирает шум | меньше отказов |
| Ссылка на правило | доверие и обучение | сильнее удержание |
| Счётчик «ошибок на 100 слов» | измеримость | повод вернуться |

### P1 — сильные дифференциаторы (3–6 недель)
| Изменение | Зачем |
| --- | --- |
| Персональный словарь терминов | без него не работают юристы, медики, айти |
| Загрузка и проверка файлов DOCX/PDF | рабочий сценарий, а не демо |
| История версий и «до/после» | контроль правок |
| Светлая тема и настройки строгости | разные аудитории |
| Быстрый блок «вода / тошнота / читаемость» после каждого действия | доказательство пользы |
| Синонимы к повторяющимся словам | прямой ответ на «тошноту» |

### P2 — расширение поверхности (6–12 недель)
| Изменение | Зачем |
| --- | --- |
| Браузерное расширение | проверка там, где пишут |
| Telegram-бот | дешёвая точка входа |
| API и вебхуки | B2B-сценарий |
| Экспорт DOCX/PDF | закрывает цикл работы |
| Личная статистика и прогресс | привычка возвращаться |
| Командные отчёты | корпоративный спрос |

## 5. UX-детали, которые дают больше всего

1. Ошибка должна быть кликабельной прямо в тексте, а не только в списке.
2. После применения правки — мгновенное подтверждение и переход к следующей.
3. Показывать «было → стало» в одном месте.
4. Не блокировать кнопку проверки, если текст пуст, — объяснять, что делать.
5. Единый индикатор состояния: «проверено 2 минуты назад».
6. Состояние загрузки с этапами: «проверяю орфографию → стиль».
7. Пустые состояния с примером и кнопкой «вставить пример».
8. Ограничения показывать до действия, а не после (сколько знаков осталось).
9. Мобильная панель правок снизу, как сейчас у ассистента.
10. Каждая правка — с коротким объяснением, а не только «заменить».

## 6. Технические улучшения

- Серверная проверка с собственным экземпляром LanguageTool вместо публичного API:
  снимает лимиты и решает вопрос приватности текста.
- Хранение лимитов и статистики в базе, а не в памяти процесса.
- Очередь и таймауты на проверку длинных текстов, чанки по 5000 знаков.
- Кеш правок на уровне документа и нормализованные ключи.
- Тесты правил: корпус «плохой текст → ожидаемый результат» (регрессия при
  добавлении новых правил).
- Метрики продукта: время до первой правки, доля принятых правок, повторные
  визиты, средняя длина текста, конверсия «вставил текст → нажал проверить».

## 7. Что измерять

| Метрика | Как считать | Ориентир |
| --- | --- | --- |
| Доля принятых правок | применённые / предложенные | > 40% |
| Время до первой правки | от вставки текста до клика | < 20 c |
| Повторные визиты | за 7 дней | > 25% |
| Средняя длина текста | символы | 800–2000 |
| Ошибок на 100 слов до/после | по метрикам | −60% |

## 9. Статус внедрения в текущем приложении

Реализовано:

- Тема интерфейса переключается и запоминается.
- История версий и статистика проверок/принятых исправлений сохраняются в
  браузере вместе с черновиком и словарём.
- Настройки проверки разделены на режимы «мягко», «строго» и «только ошибки».
- Экспорт PDF выполняется через печать браузера; DOCX и TXT доступны отдельно.
- Текстовые PDF до 5 МБ извлекаются PDF.js локально в браузере; сканы требуют OCR.
- Для замечаний LanguageTool добавлены ссылки на подробности правила.
- Историю версий можно сравнить с текущим текстом в двух колонках с разницей
  в числе слов и символов.
- После AI-правки исходный фрагмент и результат можно развернуть рядом;
  отображается разница в количестве слов.
- Для GitHub Pages создан статический клиент; он использует текущий Vercel API
  и ограниченный CORS origin `https://goviks.github.io`.
- Проверка LanguageTool принимает тексты до 50 000 символов, отправляя их
  частями до 5000 символов. Адрес сервиса задаётся через `LANGUAGETOOL_URL`;
  по умолчанию используется публичный endpoint.
- При загрузке документа свыше лимита приложение сообщает об этом, а не
  обрезает содержимое незаметно.

Пока не реализовано: облачная синхронизация/учётные записи, постоянное хранилище
лимитов на сервере, браузерное расширение, плагины Word и
Google Docs, командная аналитика, OCR, детектор ИИ и проверка уникальности. Эти
интеграции требуют отдельной инфраструктуры и/или внешних источников данных.
Telegram-бот и Docker в текущий план внедрения не входят.
